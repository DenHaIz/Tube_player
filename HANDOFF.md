# Tube — передача проекта

Документ для того, кто продолжит работу: что это, как устроено, как собирать и выпускать, где грабли.

## Что это

Два Android-приложения для просмотра YouTube в России без внешних серверов, на общем ядре обхода DPI (byedpi, как ByeDPI/zapret):

- **Tube** (`:app`, `com.tube.dpi`) — локальный VPN только для выбранных приложений (YouTube, ReVanced, Morphe, Music, GmsCore) пропускает их трафик через byedpi. Репозиторий https://github.com/DenHaIz/Tube_DPI.
- **Tube Player** (`:client`, `com.tube.player`) — свой лёгкий клиент YouTube (NewPipeExtractor + Media3) со встроенным byedpi, без VPN. Репозиторий https://github.com/DenHaIz/Tube_player. Подробно — раздел «Tube Player» ниже.
- minSdk 26, targetSdk 36, compileSdk 37. Лицензия GPL-3.0.

## Стек

Kotlin + Jetpack Compose (BOM 2026.09.00), AGP 9.4.1, Gradle 9.8.2, NDK 29.0.14206865, DataStore, Haze (стекло), Robolectric + Roborazzi. Без DI-фреймворков и навигации: ручной `AppContainer`, свои экраны и стеклянные листы. Дизайн-основа перенесена из Woody (`..\Android TODO`). Tube Player дополнительно: NewPipeExtractor 0.27.1 (JitPack, только группа `com.github.TeamNewPipe`), Media3 1.11.1, OkHttp 5.5.1, Coil 3, androidx.webkit.

## Устройство

```
YouTube / ReVanced / Morphe ─► TUN (VpnService, addAllowedApplication)
   ─► hev-socks5-tunnel (mapdns: DNS отвечает сам, в SOCKS уходит имя сайта)
   ─► SOCKS5 127.0.0.1:<свободный порт> ─► byedpi (отдельный процесс) ─► интернет
                                   └─ имена резолвит через LocalDns (127.0.0.1) → DoH 8.8.8.8 / 1.1.1.1
```

Ключевые решения и почему:
- **byedpi — отдельный процесс, а не библиотека.** У него глобальное состояние (params, getopt). Процесс изолирует падения и позволяет тестеру запускать 6 стратегий параллельно на разных портах. APK собран с `jniLibs.useLegacyPackaging = true`, иначе исполняемый файл не распакуется в `nativeLibraryDir`.
- **DNS через DoH.** С февраля 2026 национальный DNS (НСДИ) не отдаёт youtube.com. `getaddrinfo` в byedpi подменён при линковке (`-Wl,--wrap=getaddrinfo`, `core-byedpi/src/main/cpp/tube_dns.c`): если задан `TUBE_DNS`, запрос уходит на `LocalDns` приложения, тот ходит в DoH по IP (без SNI). Исходники byedpi не патчим.
- **mapdns в hev** выдаёт приложениям адреса из 198.19.0.0/16 (не 100.64/10 — это CGNAT мобильных операторов) и передаёт в SOCKS имя сайта.
- **QUIC** по умолчанию запрещён (`byedpi -U`): YouTube уходит на TCP, где работает desync.
- **Порты byedpi случайные свободные** (`ByeDpiProcess.freePort`) — и у VPN, и у тестера: фиксированные порты сталкивались (сторож и «Проверить» одновременно → «ошибка»). `start` ждёт, пока порт освободится, `stop` ждёт смерти процесса.
- **byedpi резолвит имена синхронно в единственном потоке** — пока ждёт DNS, стоят все соединения. Поэтому `LocalDns` держит keep-alive к DoH, отдаёт устаревший ответ сразу (обновляя в фоне, до суток) и при старте VPN/подбора заранее запрашивает адреса YouTube и кластера видеоузлов (`prefetch`). Запросы byedpi и фоновые обновления — в разных ограниченных пулах; одинаковые запросы объединяются; сначала опрашивается последний ответивший DoH, через 1,2 с — остальные параллельно; при неудаче сразу SERVFAIL. `tube_dns.c`: `connect()`-сокет (чужие датаграммы отбрасываются), id из `arc4random`, проверка QR, 2 попытки по 2,5 с.
- **Сервис VPN** (`TubeVpnService`): все изменения под `Mutex`; останавливается только по последней команде (`stopSelfResult(startId)`), поэтому «выкл → вкл» подряд не убивает новый туннель. Перезапуск поднимает новый byedpi и новый TUN до закрытия старых — трафик YouTube не уходит мимо VPN. Ошибки запуска → `Failed`, а не падение процесса (`CoroutineExceptionHandler`). `onDestroy` отменяет запуск и разбирает туннель под замком в `container.scope`.
- **ResultsStore** пишет `results.json` через `AtomicFile`, в фоне и не чаще раза в 1,5 с (подбор шлёт ~100 обновлений).
- **AutoPick** — один подбор за раз (`AtomicBoolean`), «Стоп» отменяет и подбор, запущенный сторожем. Запуск byedpi в тестере не прерывается отменой (`NonCancellable`) и всегда останавливается — процессы не теряются.
- **Tube не входит в собственный VPN**, поэтому соединения byedpi идут напрямую, `protect()` не нужен.

### Подбор стратегий (`AutoPick` + `StrategyTester`)

1. Проверка системного DNS и поиск **настоящего видеоузла** сети: страница `youtube.com/watch` читается через текущую/рабочие стратегии до первой ссылки `rrN---sn-….googlevideo.com` (~790 КБ от начала страницы). Ответ `redirector/report_mapping` зашифрован и шифр меняется — не использовать.
2. Пробы для каждой стратегии (все должны пройти):
   - `www.youtube.com` и `i.ytimg.com`: полный TLS (Java) + загрузка > 64 / 8 КБ (видно замедление «замирает после 16 КБ»);
   - видеоузел: TLS + `/generate_204`;
   - сайт, `youtubei.googleapis.com` (API приложения), превью и видеоузел: **ClientHello как у Chrome** (`ChromeHello`, шаблон `tls_clienthello_vk_com_kyber.bin` ~1.8 КБ с Kyber и GREASE ECH, SNI подставляется) — сервер должен ответить ≥ 2 КБ. На каждый узел **три** ClientHello с разным порядком расширений: SNI в начале, SNI в конце (после key_share и ECH, во втором TCP-сегменте) и случайный — Chrome/Cronet переставляет расширения в каждом соединении.
   Без проверки «как у Chrome» в v0.2 часть стратегий проходила тест, но не пропускала видео в приложении: короткий Java-ClientHello DPI разбирает иначе, чем большой ClientHello Cronet. В v0.3 порядок расширений был всегда как в шаблоне (SNI ~150-й байт) — стратегии с фиксированными смещениями проходили тест, а в YouTube работали через раз.
   - Второй круг (`AutoPick.verify`): прошедшие (до 16) проверяются ещё раз по две за раз; не прошедшие повторно уходят из «рабочих».
3. Результаты пишутся в `ResultsStore` (`filesDir/results.json`) по ключу сети (`NetworkMonitor`: Wi-Fi — шлюз + DNS роутера, мобильная — MCC/MNC), вместе с выбранной для сети стратегией и видеоузлом.

### Сторож (`StrategyWatchdog`, запускается из `TubeVpnService`)

Первая проверка через 15 с после включения, дальше раз в 10 минут — пробы через работающий прокси. Два провала подряд (повтор через 15 с) при живом интернете (`ya.ru`, `gstatic`): пробует до 6 рабочих стратегий этой сети, если нет — полный подбор в фоне (не чаще раза в час). Провал в VPN записывается в результаты сети — стратегия уходит из «рабочих». При смене сети подставляет запомненную для неё стратегию. Смена — через `ACTION_RESTART` сервиса + уведомление.

### Автозапуск

`AutoStartService` получает только `TYPE_WINDOW_STATE_CHANGED` (имя пакета, без содержимого окон). Логика в `AutoStartPolicy` (покрыта тестами): включить при выходе выбранного приложения на экран; выключить через N минут после ухода, только если включал автозапуск и через туннель нет трафика (фоновое воспроизведение).

### Обновления

`UpdateChecker` узнаёт версию по очереди: API GitHub → API через `gh-proxy.com` → редирект `github.com/…/releases/latest` → `/tag/vX.Y` напрямую и через `ghfast.top`/`ghproxy.net`. APK качается с GitHub, затем через зеркала `ghfast.top`, `gh-proxy.com`, `gh-proxy.org`, `ghproxy.net` (проверены в ноябре 2026). Каждый скачанный файл проверяется: размер, SHA-256 из поля `digest` API, имя пакета, версия новее и та же подпись, что у установленного приложения — подмена зеркалом до установщика не дойдёт. Сравнивает `tag_name` с `versionName`, качает первый `.apk` из ассетов в `cacheDir/updates` и открывает системный установщик через FileProvider (`${applicationId}.files`). **Значит, у каждого релиза должен быть APK `Tube-X.Y.apk` и тег `vX.Y`.** До 0.4 проверка всегда падала: заголовок `Accept` ставился после `responseCode` («Already connected»).

## Tube Player (`:client`)

```
NewPipeExtractor ─┐
Media3 (видео) ───┤                                  ┌─ byedpi (процесс libbyedpi.so) ─► интернет
Coil (превью) ────┼─► OkHttp ─► BypassProxySelector ─┤   имена резолвит LocalDns → DoH
InnerTube, SB, RYD┘   (SOCKS5, хост неразрешённым)   └─ «Без обхода»: DIRECT, имена через DoH (DohDns)
WebView входа ─► androidx.webkit ProxyController ─► тот же SOCKS-порт
```

- **Адрес прокси — только `127.0.0.1` (IPv4).** byedpi слушает его одного; `InetAddress.getLoopbackAddress()` на части телефонов отдаёт `::1` — в 0.1 из-за этого все запросы приложения получали «Connection refused», а сторож (он ходит в byedpi сам через `Socks5`, по 127.0.0.1) считал обход рабочим. Теперь `BypassProxySelector.Loopback4`, а `BypassController` раз в 10 минут проверяет и путь самого приложения (OkHttp → byedpi → `youtube.com/generate_204`): `Running.appOk` — красная точка и причина в листе обхода. Пока byedpi запускается, запросы ждут его (`ProxyGate`, до 10 с), а не уходят напрямую.
- **Через byedpi — только YouTube и Google** (`BypassProxySelector.needsBypass`: youtube.com, googlevideo.com, ytimg.com, ggpht.com, googleusercontent.com, googleapis.com, google.com, gstatic.com…). Остальное (SponsorBlock, Return YouTube Dislike) — напрямую с DoH: в 0.2 стратегии, подобранные под YouTube, ломали TLS к этим сайтам, и «плагины» молчали.
- **Обход без VPN.** `net/BypassProxy` поднимает byedpi на `ByeDpiProcess.freePort()`; `BypassController` берёт стратегию сети (`ResultsStore.chosen`) или из настроек и запускает сторож из `:core-strategy` (первая проверка через 5 с); при сбое — замена или полный подбор в фоне. Порт меняется при смене стратегии: OkHttp читает его в `ProxySelector` на каждом новом соединении, пул сбрасывается (`AppContainer.start`). Плеер работает рядом с любым VPN.
- **Видео.** `youtube/Repository` — NewPipe (поиск, киоски `trending_music/gaming/movies_and_shows/podcasts_episodes`, `live`; канал, плейлист, RSS канала, `StreamInfo`). Обычного «Trending» в NewPipe 0.27 нет. Потоки NewPipe 0.27 отдаёт от клиента **VISIONOS**: загрузка идёт POST с телом `x\0`, параметром `rn` и User-Agent visionOS (`player/YoutubeDataSource`, как `YoutubeHttpDataSource` у NewPipe), редиректы — с сохранением POST (`KeepPostRedirects`, клиент без followRedirects).
- **DASH.** `player/DashManifest` собирает один MPD на всё видео: AdaptationSet на семейство кодека (avc1, vp9; AV1 не берём — программный декодер), все качества внутри → в Media3 работают «Авто» (ABR) и ручной выбор (`TrackSelectionOverride`); предел качества по сети (Wi-Fi/мобильная) — `setMaxVideoSize`. Нет индексов → видео+звук (`MergingMediaSource`), совсем старые → itag 18, эфиры → HLS. 403/410 (ссылки протухли) → заново `StreamInfo` и продолжение с той же позиции.
- **Видео — на TextureView** и на странице, и в мини-плеере: SurfaceView — «дыра» под окном, не обрезается и отстаёт от анимаций (при свайпе видео «проваливалось» под текст). Свой `ui/VideoSurface`, **не `ContentFrame`**: `ContentFrame` вызывает `setVideoTextureView` сразу, когда у нового TextureView ещё нет поверхности, — плеер на миг остаётся без вывода, и при сворачивании мини-плеер был чёрным около секунды. `VideoSurface` отдаёт плееру поверхность только когда она готова (`onSurfaceTextureAvailable` → `setVideoSurface`), переключение со старой на новую — сразу; старый вид держит последний кадр, под новым до первого кадра — обложка. Побеждает тот, кто подключился последним; `clearVideoSurface` у уходящего снимает только свою. **Экран не гаснет**, пока видео играет: `VideoSurface(keepScreenOn)` ставит `View.keepScreenOn` (стандартный PlayerView делает это сам, свой вид — нет; в 0.4.3 и раньше экран гас во время просмотра), в плавающем окне — `root.keepScreenOn` по `onIsPlayingChanged`.
- **Плеер страницы — один на все раскладки** (`movablePlayer`, `movableContentOf` + `PlayerSlot` с текущими значениями): при входе/выходе из полноэкранного режима и повороте он переносится, а не создаётся заново — раньше на планшете каждый раз мелькала обложка (новый TextureView ждал первый кадр). `VideoSurface` при этом держит SurfaceTexture сам (`onSurfaceTextureDestroyed` → false, при возвращении вида — `setSurfaceTexture`), освобождает в `release`. На планшете боком (размер окна не меняется) границы плеера плавно анимируются (`LookaheadScope` + `Modifier.animateBounds`, пружина без перелёта), углы 12dp → 0, фон страницы темнеет, описание и похожие проявляются (`fadeInOnAppear`); при повороте и смене размера окна — сразу на место (`PlayerSlot.animate`). На планшете боком плеер закреплён сверху слева, под ним прокручивается описание.
- **Сворачивание свайпом:** мини-плеер появляется, когда страница прошла ~60% пути вниз, а не после того, как пружина успокоится у края (раньше между ними была пустая пауза); при повторном открытии смещение сбрасывается (`VideoScreen(visible)`).
- **Свайп: координаты окна.** Плеер едет вместе со страницей, поэтому положение пальца считается в координатах окна (`LayoutCoordinates.localToWindow`), а не плеера — иначе собственное движение страницы попадало обратно в жест и давало рывки. Скорость отпускания — `VelocityTracker`: быстрый взмах сворачивает и на коротком пути. После порога страница доезжает вниз пружиной с той же скоростью, и смещение **не сбрасывается** (в 0.4 сброс в 0 давал откат и «окно на секунду» во время анимации выхода); страница открывается и уходит снизу целиком.
- **Свайп вниз** двигает всю страницу видео за пальцем (`VideoScreen`: сдвиг, лёгкое уменьшение, затухание), после порога страница доезжает вниз и становится мини-плеером. **Зум** — масштаб слоя (`graphicsLayer`) от «вписано» до «заполнить экран», щипок ведёт масштаб за пальцами, потом пружина. **Плавающее окно**: сначала приложение уходит в фон (видео ещё на экране), через 220 мс окно «вырастает» из правого нижнего угла по первому кадру, затем экран приложения отдаёт поверхность.
- **Комментарии** — разделители между авторами (у первого нет — под заголовком уже линия), имя автора выделено, у автора канала — плашка, ответы сдвинуты с линией ветки слева, стрелка «N ответов» поворачивается. `Repository.comments` (NewPipe `CommentsInfo`, страницы и ответы по `Page`), `CommentsModel` в `MainViewModel`, `CommentsPreview` под описанием и `CommentsPanel`, выезжающая под плеером (закрывается «назад»).
- **Превью** — `thumbnailCandidates`: сначала `i.ytimg.com/vi_webp/<id>/hq720.webp` (1280×720, ~28 КБ против ~65 КБ у JPEG), не нашлось — то, что отдал YouTube; `NetImage` перебирает адреса и масштабирует с `FilterQuality.High` (по умолчанию Low — отсюда «пиксели»). Аватары запрашиваются крупнее (`sharpAvatar`: `=s88` → `=s176`).
- **Удержание в правой половине видео — ×2**, пока палец на экране (подсказка «2×» сверху; `onPress` + `tryAwaitRelease`, `onLongPress = {}` — чтобы отпускание не считалось тапом); прежняя скорость возвращается.
- **PiP жестом «домой»** (`setAutoEnterEnabled`): `setSourceRectHint` — положение плеера (`VideoActions.onPlayerBounds` → активность, обновление не чаще раза в 150 мс), и окно вырастает из видео; под открытым видео фон окна чёрный (`window.setBackgroundDrawable`), иначе в переходе был виден светлый фон темы — «белый экран».
- **Жесты плеера — как в YouTube** (`PlayerView`): тап — контролы, сразу (двойной тап распознаётся вручную по двум `onTap` в пределах 300 мс в одной половине; `onDoubleTap` у `detectTapGestures` задерживал одиночный тап на ~0,3 с); двойной тап слева/справа — ±10 с, следующие тапы в течение 0,8 с добавляют ещё по 10 с (подсказка — полукруг на стороне тапа, сторона хранится отдельно, иначе исчезающая подсказка «прыгала» на другую сторону); смахнуть вниз — мини-плеер (во весь экран — выход из него), вверх — во весь экран; щипок во весь экран — растянуть без рамок (`ContentScale.Crop`), есть и кнопка. Яркость и громкость жестами не меняются — видео с яркостью устройства.
- **Лайки** — `Library.liked`/`disliked` (работают без аккаунта, раздел «Понравившиеся» во вкладке «Вы»), при входе — ещё и `InnerTube` like/dislike/removelike. Даты — `Format.uploaded`: YouTube отдаёт для страницы видео и RSS дату ISO, её превращаем в «3 дня назад».
- **Плеер** (`PlayerController`) — один ExoPlayer на процесс; старт после ~1 с буфера (`DefaultLoadControl` 15/50/1/2 с, на устройствах с малой памятью — до 30 с); «Авто» не выше разрешения экрана (`setViewportSizeToPhysicalDisplaySize`), ручной выбор не ограничен; `Repository.video` кэширует данные видео на 30 минут (повторное открытие без сети, при 403 — `fresh = true`); `PlaybackService` (MediaSessionService) — уведомление, фон, обложка через тот же OkHttp. PiP — `setAutoEnterEnabled` на 12+, `onUserLeaveHint` на 8–11, кнопка пауза/играть. Плавающее окно — `PopupPlayer` (переход: сначала экран отдаёт поверхность, через 120 мс окно забирает плеер и проявляется по первому кадру, только потом приложение уходит в фон — иначе белая вспышка и застывший кадр) (`TYPE_APPLICATION_OVERLAY`, TextureView, перетаскивание, щипок, двойной тап — развернуть, бросок вниз — закрыть); нужно разрешение «Поверх других приложений».
- **Без рекламы.** Ролики идут не через плеер YouTube — рекламы в них нет; `AdBlock` режет рекламные и следящие адреса в OkHttp и WebView и выкидывает рекламные элементы выдачи InnerTube (`adSlotRenderer`, `promotedVideoRenderer` …). **SponsorBlock** — запрос по 4 символам SHA-256 id видео, категории: пропуск / кнопка / метка / нет; отрезки на полосе прокрутки, «Отменить» после пропуска. **Return YouTube Dislike** — дизлайки.
- **Аккаунт — необязательный.** Сначала системный выбор аккаунта (`AccountManager.newChooseAccountIntent`, приложение получает только адрес): адрес подставляется на страницу входа (`Email=`/`login_hint`), и Google предлагает подтвердить вход на телефоне или ключом доступа. Взять сессию YouTube у системного аккаунта Google стороннее приложение не может (токены `weblogin:` выдаются только приложениям Google; ReVanced для этого нужен MicroG). `LoginScreen`: WebView на accounts.google.com через byedpi (`ProxyController`, UA без `wv`); после входа cookie youtube.com (SAPISID…) и `VISITOR_DATA` → `AccountStore` (файл, AES-GCM ключом Android Keystore). `InnerTube`: `browse` FEwhat_to_watch / FEsubscriptions / FEchannels, `Authorization: SAPISIDHASH`, разбор готовыми экстракторами NewPipe (`YoutubeStreamInfoItemExtractor`, `…LockupExtractor`). NewPipe всегда анонимный — cookie туда не передаются. Без входа «Для вас» = похожие на недавно просмотренные, подписки — локальные (RSS).
- **Данные** — JSON + `AtomicFile` (`data/Library`: история до 1000, позиции, подписки, поиск), настройки — DataStore. Room не нужен.
- **Интерфейс — как оригинальный YouTube** (по просьбе владельца, в отличие от Tube): текст слева, аватар рядом с заголовком, превью во всю ширину на телефоне и сетка на планшете, чипы 32dp, «Подписаться» справа, нижняя панель Главная / Подписки / Вы, мини-плеер над ней. Палитра `TubePalette.Violet` (без зелёного), AMOLED. **Листы** — заголовок по центру (`SheetTitle`); в настройках «Аккаунт» и «Обход блокировок» открыты всегда, остальные разделы свёрнуты в «шторки» с названием по центру (`SettingsShutter(collapsible)`), профиль в «Аккаунте» и лист аккаунта — по центру. Лист качества на низком экране (во весь экран, телефон боком) — без заголовка, ползунки качества и скорости рядом, не листается. В AMOLED разделители комментариев светлее (`commentDivider`). **Планшет боком** (ширина ≥ `WideMin` 840dp и больше высоты): всё управление — в панели у **правого** края во всю высоту (`NavRail`, 96dp), верхней панели нет — контент начинается от строки состояния. Сверху логотип «Tube» (`Brand(compact)`: «Player» плавно сжимается при повороте, `railChanged` — чтобы переход показался), по нажатию — меню «Обход блокировок» / «Настройки» (`BrandMenu`, точка — состояние обхода); под ним крупная круглая кнопка поиска, линия и крупные вкладки, равномерно по высоте. На вложенных экранах (поиск, канал, плейлист) верхняя панель с «назад» и полем поиска остаётся, но без значков и до боковой панели. Внизу только мини-плеер; страница видео — плеер со скруглением и описание слева, похожие (и панель комментариев) справа компактными строками, поля симметричные — 16dp от краёв и между колонками (если высота ≥ 480dp; телефон боком — плеер на весь экран). **Листы на планшете боком** (`GlassSheet(dockToSide = true)`, ширина ≥ 840dp и больше высоты) — панель у правого края во всю высоту (38% ширины, 380–480dp), выезжает справа и закрывается свайпом вправо, тапом по фону или «назад»; снизу по центру лист оставлял пустые поля. В `:app` параметр не включён — там поведение прежнее. **Планшет стоя** (ширина ≥ 600dp): лента в две колонки, похожие под видео — тоже в две колонки карточками, мини-плеер — скруглённая карточка с полями (`MiniCardExtra`), а не полоса во всю ширину. Анимации быстрые и плавные (`ui/Anim`, 120–250 мс). Логотип — скруглённая кнопка «play» с нежно-фиолетовым градиентом и бежевой окантовкой (окантовка рисуется под заливкой, иначе внутренние углы острые).
- Навигация своя: вкладки + стек `Route` в `MainViewModel`, страница видео — слой поверх (свернуть = мини-плеер). Телефон боком с открытым видео — плеер на весь экран без панелей; ширина ≥ 900dp — похожие справа.

Проверки: `LogicTest` (SAPISIDHASH, SponsorBlock, MPD + разбор Media3, правила запросов googlevideo, AdBlock, разбор InnerTube, библиотека), `PipelineNetworkTest` (`-Pnetwork`: поиск, киоск, подсказки, `StreamInfo`, 256 КБ видео и звука через SOCKS, ExoPlayer доходит до READY и играет 2 с), `ScreenshotTest` (`-Pscreenshots`: главная светлая / AMOLED / EN / боком / планшет / планшет с мини-плеером, планшет стоя (`tablet_port_*`: главная, видео, настройки, комментарии) и боком (`tablet_land_*`: настройки, качество, комментарии, поиск, библиотека, канал), мини-плеер, комментарии светлые / AMOLED, лист качества боком, раскрытые настройки, поиск, видео телефон / AMOLED / планшет, канал, библиотека, подписки, листы, логотип). ## Сборка на сервере разработки

Тулчейн общий с Woody: `.toolchain` — junction на `..\Android TODO\.toolchain` (создаётся `env.ps1`). Путь без пробелов обязателен: ndk-build падает на пробеле в «Android TODO», а 8.3-имена Gradle разворачивает обратно. NDK 29 доставлен в общий SDK; `sdkmanager` устарел — `cmdline-tools\latest\bin\android.exe sdk install <пакет>`.

```powershell
git submodule update --init --recursive
. .\env.ps1
.\gradlew.bat testDebugUnitTest                         # логика (Robolectric, @Config(sdk = [35]))
.\gradlew.bat :app:testDebugUnitTest -Pscreenshots      # скриншоты → app\build\outputs\roborazzi
.\gradlew.bat :core-byedpi:testDebugUnitTest -Pnetwork  # проверки через настоящий интернет (DoH, пробы, Chrome-hello)
.\gradlew.bat :app:lintDebug :app:assembleRelease
.\gradlew.bat :client:testDebugUnitTest -Pscreenshots   # → client\build\outputs\roborazzi
.\gradlew.bat :client:testDebugUnitTest -Pnetwork --tests "*PipelineNetworkTest*"
.\gradlew.bat :client:lintDebug :client:assembleRelease
```

- Эмулятора нет. Визуальная проверка — только скриншоты Roborazzi; сеть — тесты `-Pnetwork`.
- Сервер стоит в Финляндии: YouTube здесь не блокируется, поэтому `-Pnetwork` проверяет только «трубопровод» (SOCKS, TLS, DoH, ClientHello), а не обход DPI. Работу стратегий проверяет владелец на телефоне в РФ.
- Robolectric без `@Config(sdk = [35])` падает на SDK 36 (`FileDescriptor internals`).

## Грабли

- **Bash-инструмент портит `\\` в heredoc** (превращает в настоящие переводы строк/склеивает строки). Для правок с экранированием писать Python-скрипт в файл и запускать его, либо пользоваться Edit.
- Шаблоны/фейки в `assets/fake` подставляются в аргументы как `@fake/<файл>`, фейковый SNI — как `{sni}` (`ByeDpiProcess.start`).
- `-S` (md5sig) может не работать на ядрах Android — такие стратегии просто не проходят тест.
- С ноября 2026 у ТТК, Ростелекома, Дом.ру тормозят видео вне кэша GGC провайдера — это не DPI, стратегии не помогут.
- Android 13+ для APK не из магазина: прежде чем включать службу спецвозможностей, нужно «Сведения о приложении → ⋮ → Разрешить ограниченные настройки».
- **Горизонтальный вид и планшеты:** главный экран при ширине > высоты и ≥ 560dp — кнопка слева, карточки справа; на узких — колонка до 560dp. Отступы — `WindowInsets.safeDrawing` (вырез камеры сбоку). Листы (`GlassSheet`) не шире 640dp. Скриншоты: `home_landscape_phone`, `home_tablet_land`, `sheet_strategy_tablet`, `sheet_settings_landscape`.
- **Стратегии с `-A`:** запасная группа должна делать настоящий обход. Пустая (как была в OOB TIMEOUT до 0.5) после первого сбоя запоминает IP «без обхода» навсегда (cache-ttl по умолчанию 0). Последняя группа без `-K`/`-H`/детекта нужна для прочего трафика (BEELINE до 0.5 его отбрасывал).
- **`-Y` и `-S`** на ядрах, где запрещены SO_ATTACH_FILTER/TCP_MD5SIG, обрывают соединение — такие стратегии просто не проходят подбор.
- Release подписан debug-ключом тулчейна: смена ключа сломает обновление у всех пользователей. Ключ хранить, наружу не отдавать.
- Предпочтения владельца по интерфейсу Tube: почти весь текст по центру, коротко, без мелкого шрифта (`labelSmall` не использовать для пояснений), главный экран без прокрутки. **Tube Player — наоборот, как оригинальный YouTube** (слева, расположение и размеры кнопок как у YouTube), без зелёного.
- **Lint и Media3:** opt-in `UnstableApi` из `compilerOptions` lint не видит — в файлах с Media3 нужен `@file:androidx.annotation.OptIn(markerClass = [UnstableApi::class])`.
- **nanojson** — runtime-зависимость NewPipeExtractor; для разбора InnerTube подключена явно (та же версия-коммит).
- **Robolectric:** `PlayerApp` не запускает обход при `Build.FINGERPRINT == "robolectric"`; Keystore в тестах недоступен — `AccountStore` молча не пишет файл.
